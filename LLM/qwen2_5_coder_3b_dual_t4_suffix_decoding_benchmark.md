# Suffix Decoding Benchmark: Qwen2.5-Coder-3B on Dual Tesla T4

**Date:** October 14, 2026  
**Hardware Environment:** $2 \times \text{NVIDIA Tesla T4}$ (15,360 MiB VRAM each; single GPU used for latency measurements), Intel Xeon @ 2.00 GHz (4 vCPUs), 31 GiB Host RAM  
**Target Model:** `Qwen/Qwen2.5-Coder-3B-Instruct`  
**Primary Method:** SuffixDecoding using Snowflake ArcticInference

---

## 1. Executive Summary

I investigated **SuffixDecoding**, a NeurIPS 2025 Spotlight method that replaces
a learned speculative draft model with a CPU suffix tree over prompts and prior
outputs. The practical question was sharper than the paper's headline: **can a
small history of outputs accelerate a 3B model on an old T4, and is the gain
selective rather than universal?**

Yes. On six held-out structured JSON requests generated by
`Qwen/Qwen2.5-Coder-3B-Instruct`, 14 prior outputs increased median throughput
from **21.35 to 151.37 output tokens/s (7.09x)**. Hugging Face prompt lookup
reached only **24.29 tokens/s (1.14x)**. Every accelerated sequence exactly
matched independent greedy decoding, token for token. Peak allocated VRAM rose
only from **5915 to 5957 MiB** (+42 MiB).

The important qualification is workload selectivity. On six unrelated,
open-ended prompts, suffix decoding delivered only **1.06x**, while prompt lookup
regressed to **0.954x**. Suffix draft acceptance fell from **82.1% to 20.6%**.
Thus the defensible finding is not “suffix decoding makes LLMs 7x faster”; it is:

> Repeated output schemas turn previous generations into an extremely effective,
> training-free draft model, but retrieval speculation should be workload-gated.

An additional cache-size ablation found a non-monotonic effect: one prior example
already helped strongly, eight were best, and fourteen were slightly worse. More
history is not automatically better because frequency collisions can select a
worse continuation.

## 2. Research Landscape

### Primary work

- **Oliaro, Jia, Campos, Qiao, “SuffixDecoding: Extreme Speculative Decoding for
  Emerging AI Applications,” arXiv v3, 7 Oct 2025; NeurIPS 2025 Spotlight.**
  [Paper](https://arxiv.org/abs/2411.04975),
  [proceedings](https://proceedings.neurips.cc/paper_files/paper/2025/hash/b7aea253ab34a773967f1e4cdea9e4fb-Abstract-Conference.html),
  [official code](https://github.com/snowflakedb/ArcticInference).
  It stores current and historical token strings in local/global suffix trees,
  estimates continuation probability from frequency, and scales draft length
  with matched-suffix length. The paper reports up to 5.3x on AgenticSQL and
  2.5x on SWE-Bench using Llama-3.1-8B on H100 hardware. Those exact benchmark
  claims were **not** reproduced here.

- **Hu et al., “SAM Decoding: Speculative Decoding via Suffix Automaton,”
  16 Dec 2024.** [Paper](https://arxiv.org/abs/2411.10666),
  [code](https://github.com/hyx1999/SAM-Decoding). It independently supports the
  broader idea: static corpus plus dynamic sequence retrieval, with amortized
  O(1) automaton transitions, beat retrieval baselines by 18%+ in its setup.

### Foundations and baseline

- **Chen et al., “Accelerating Large Language Model Decoding with Speculative
  Sampling,” 2 Feb 2023.** [Paper](https://arxiv.org/abs/2302.01318). It explains
  why a target model can verify several proposed tokens in one parallel pass and
  preserve its output distribution. In this experiment deterministic greedy
  verification gave exact token equality.
- **Apoorv Saxena, “Prompt Lookup Decoding,” Nov 2023.**
  [Code and description](https://github.com/apoorvumang/prompt-lookup-decoding).
  It drafts from n-grams already present in the current prompt/sequence and is
  now integrated in Transformers and vLLM. This was the model-free baseline.

I also surveyed recent directions including SWIFT self-speculation, KV-cache
quantization/compression, adaptive reasoning exits, and sparse attention. Most
had a less favorable combination of T4 compatibility, implementation risk,
objective measurement, and runtime. Suffix decoding required no extra GPU model,
had official CPU code, and exposed a clean hypothesis about repeated agents.

## 3. Research Hypothesis

**Hypothesis.** If an agent emits a stable output schema, a suffix index over a
small number of prior target-model outputs will propose long accepted runs,
reducing expensive target-model decode steps and outperforming prompt-only
n-gram lookup. It should not materially help unrelated open-ended prompts.

Support required: exact output parity, higher tokens/s on held-out structured
requests, high acceptance, and a much smaller gain on a non-repetitive control.
The results satisfy all four conditions.

## 4. Experimental Methodology

### 4.1 Environment

- Kaggle batch container; network access and package installation worked.
- **2x NVIDIA Tesla T4, 15,360 MiB each**, driver 580.178.04.
- CUDA exposed by driver 13.0; PyTorch runtime CUDA 12.8.
- Python 3.13.15, PyTorch 2.11.0+cu128, Transformers 5.16.1.
- 4 logical Xeon CPUs, 31 GiB RAM, no swap, 20 GiB writable
  `/kaggle/working`; `/kaggle/input` read-only.
- PyTorch saw both GPUs. A two-rank NCCL `all_reduce` returned 3.0 on both ranks,
  proving simultaneous multi-GPU operation. The latency test intentionally used
  one T4 because batch-one decoding is the target and the 3B model fits easily.
- The notebook wrapper exposed a 43,200-second cell timeout. Background process
  persistence beyond the batch lifetime was not assumed; artifacts were exported.

### 4.2 Software and Implementation

- Target: `Qwen/Qwen2.5-Coder-3B-Instruct`, FP16, SDPA, GPU 0.
- Official ArcticInference suffix-tree code at commit
  `aca5d9a8a62474035c15d114d40a01abc8c94b51`.
- Baselines: ordinary greedy autoregressive generation and Transformers prompt
  lookup (`32` candidate tokens, max n-gram 16).
- Proposed method: official `SuffixDecodingCache`, max tree depth 64,
  max draft 32, adaptive factor 1.0, minimum token probability 0.1, linear draft.
  A small adapter connects it to Transformers' standard assisted-decoding
  verifier. This integration is my modification; the suffix proposer is official.

### 4.3 Workloads and Controls

- **Structured:** 14 generated historical responses; six held-out prompts with
  varied ticket fields but an identical minified JSON schema. Output length was
  556 tokens total per trial (about 93/request).
- **Control:** six unrelated questions on science, code, energy, mathematics,
  art, and testing; 767 output tokens total per trial.
- `max_new_tokens=144`, batch size 1, greedy decoding.
- Three timed repetitions per workload/method; method order randomized.
- Each path warmed once. CUDA synchronization bracketed wall-clock timing.
  Model load, history generation, and suffix-cache construction were excluded.
- Every candidate output was compared with an independently generated vanilla
  token sequence. All 36 timed aggregate trials matched exactly.

Across repetitions, structured suffix throughput was 148.50–151.99 tok/s, while
vanilla was 21.35–21.51 tok/s. The effect is far larger than timing variation.

| Suffix diagnostic | Structured | Control |
|---|---:|---:|
| Proposed tokens / aggregate trial | 592 | 432 |
| Accepted draft tokens | 486 | 89 |
| Proposed-token acceptance | **82.1%** | **20.6%** |
| Accepted tokens / matched proposal call | 7.04 | 0.262 |

The control's low acceptance explains why cheap CPU proposals barely help: most
iterations still need ordinary target decoding. This is also a useful negative
result—blindly enabling retrieval speculation is not generally optimal.

All 18 ablation runs were exact. The new and practically useful observation is
that **a tiny history is enough, and an indiscriminately larger cache can hurt**.
The likely mechanism is frequency ambiguity: additional similar records alter
the selected continuation without adding schema information.

## 6. Technical Explanation

Autoregressive decoding normally performs one target-model pass per token. A
Transformer can instead score a short continuation in parallel. Suffix decoding
uses the cheap CPU index as a draft model:

1. Insert historical response token strings into a global suffix tree; maintain
   the current prompt/output in a local tree.
2. Match the current output suffix against indexed subsequences.
3. Rank continuations by empirical child frequency. Longer matches permit longer
   drafts; low-probability branches are filtered.
4. Run one target-model pass over the draft. Accept the longest prefix agreeing
   with greedy target predictions and retain the target's next “bonus” token.
5. Update the local/global index and repeat.

For JSON-like agent output, punctuation, key order, boilerplate, and common values
produce long repeated token paths. In our structured trial, only 70 verifier calls
produced 556 tokens, with 486 coming from accepted drafts. Open-ended text does
not share those paths, so acceptance collapses. The suffix tree resides in CPU
memory and no auxiliary network occupies VRAM.

## 7. Limitations and Confidence

- This is a **reduced-scale validation**, not reproduction of SWE-Bench,
  AgenticSQL, Llama-3.1-8B, vLLM tree verification, or H100 results.
- The structured workload is synthetic and intentionally schema-heavy; 7.09x is
  not a general-chat estimate. It nevertheless models common tool/JSON agents.
- The adapter uses linear speculation through Transformers, not ArcticInference's
  full tree verifier. That makes the demonstrated effect simpler but different.
- Only one model, one GPU type, greedy decoding, batch size 1, and six prompts per
  workload were tested. Three repetitions constrain timing noise but not workload
  sampling uncertainty.
- Cache build time is excluded, as in an online service with persistent history.
  For short-lived one-shot jobs, that amortization assumption may not hold.
- Prompt lookup instrumentation did not expose proposal counts; its wall time and
  exactness are valid, but its internal acceptance is not reported.
- Peak VRAM is PyTorch allocated memory, not board-wide energy or memory use.
- Confidence is **high** for the observed controlled result, **moderate** for the
  claim that similar structured agent services benefit, and **low** for any
  extrapolation to arbitrary workloads or production batching.

## 8. Next Steps

The strongest follow-up is a **confidence-gated hybrid router** in vLLM: use
suffix drafts only when expected accepted tokens exceed the measured break-even
point, otherwise fall back to vanilla or an EAGLE-style speculator. Evaluate on
real tool-call traces with train/test temporal splits, cache sizes from 1 to
10,000, and batch/concurrency sweeps. Measure p50/p95 latency, throughput, CPU
memory, suffix lookup time, and task quality. Two T4s are sufficient for a 7–8B
quantized target and parallel trace replay; reproducing the paper's 32B OpenHands
setup would need roughly four modern 80-GB GPUs and substantially more CPU RAM.

The cache ablation also motivates recency/domain partitioning or learned
continuation selection: retrieval quality matters more than raw cache size.
